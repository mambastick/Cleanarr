# Политика безопасности

[English](SECURITY.md) · [Русский](SECURITY_RU.md)

## Поддерживаемые версии

Активно поддерживается только последний релиз из ветки `main`.

## Сообщение об уязвимости

**Не создавайте публичный GitHub Issue для уязвимостей.**

Используйте [GitHub Security Advisories](../../security/advisories/new) и укажите:

- описание уязвимости и возможные последствия;
- шаги воспроизведения или proof of concept;
- возможный способ исправления, если он известен.

Подтверждение ожидается в течение 72 часов, исправление или план снижения риска — в течение 14 дней с учётом критичности.

## Область ответственности

CleanArr предназначен для самостоятельного размещения, обычно в домашней сети.

- Интерактивный доступ защищается локальной учётной записью, OpenID Connect SSO или обоими способами. OIDC проверяет discovery/JWKS, подпись, алгоритм, issuer, audience, срок действия, nonce и явную access policy. Если нужен локальный break-glass вход, используйте режим `both` и заранее проверьте учётную запись; в `sso_only` локальный вход намеренно отключён.
- Браузерные сессии используют `HttpOnly`, `SameSite=Strict` cookie, отдельный CSRF token и same-origin проверку мутаций. За TLS reverse proxy задайте `SESSION_COOKIE_SECURE=true`, если процесс приложения не доверяет forwarded HTTPS metadata.
- `ADMIN_SHARED_TOKEN` обходит интерактивный вход для автоматизации. Не задавайте его без необходимости и храните как привилегированный секрет.
- Webhook защищён токеном `X-Webhook-Token`. При компрометации измените его в Настройки → Общие и повторно выполните автонастройку Jellyfin.
- API-ключи сервисов, локальная учётная запись и параметры SSO хранятся в SQLite. Защищайте и резервируйте `/config` для контейнеров или `/var/lib/cleanarr` для нативных пакетов.
- Завершайте TLS на доверенном reverse proxy и не публикуйте приложение по открытому HTTP за пределами доверенной сети.
