# Torrent-клиенты

[English](TORRENT_CLIENTS.md) · [Русский](TORRENT_CLIENTS_RU.md)

CleanArr может направлять подтверждённый Arr download hash во все включённые
профили torrent-клиентов. Отсутствующий hash считается идемпотентным успешным
результатом; ошибка одного клиента фиксируется отдельно и не скрывает успешное
удаление в других клиентах.

## Поддерживаемые адаптеры

| Клиент | API | Аутентификация | Стандартный путь URL |
| --- | --- | --- | --- |
| qBittorrent | Web API v2 | cookie через username/password либо Bearer API key в qBittorrent 5.2+ | базовый URL Web UI; `/api/v2` удаляется |
| Transmission | legacy RPC и JSON-RPC 2.0 с автоматическим определением | необязательная HTTP Basic-аутентификация | `/transmission/rpc` |
| Deluge | Web JSON-RPC | пароль Deluge Web; Web UI должен быть подключён к daemon | `/json` |
| rTorrent | HTTP XML-RPC | необязательная HTTP Basic-аутентификация, обычно на reverse proxy | `/RPC2` |

Если путь указан явно, он сохраняется. Стандартный путь добавляется только к
URL без пути, поэтому схемы с reverse proxy продолжают работать.

## Поведение при удалении

Каждый адаптер поддерживает удаление только раздачи или раздачи вместе с
локальными данными. CleanArr сначала проверяет владельца по нормализованному
info hash и не превращает уже отсутствующую раздачу в ошибку.

Если включено несколько torrent-клиентов, CleanArr проверяет их все. Это нужно
для установок с распределением загрузок по инстансам и с одинаковым hash в
нескольких клиентах. Частичные ошибки аутентификации, таймаута и RPC остаются
видимыми как действия конкретного клиента.

### Политика сидирования

Для каждого профиля torrent-клиента независимо выбирается политика удаления:

- **Удалять сразу** — прежнее поведение CleanArr.
- **Оставлять раздачу** — записать skipped action и не удалять найденную раздачу.
- **Ждать выполнения условий** — проверить минимальный ratio и/или минимальное
  время раздачи. Если указаны оба порога, должны быть выполнены оба.

Политика проверяется при каждой попытке очистки. Невыполненный порог безопасно
пропускает текущую попытку; персистентное ручное задание можно повторить после
достижения порога. qBittorrent, Transmission и Deluge отдают ratio и время через
свои API. rTorrent отдаёт ratio в тысячных долях; CleanArr нормализует его и
считает прошедшее время от `d.timestamp.finished`.
Dry-run выполняет ту же проверку владельца и политики, но не вызывает удаление,
поэтому его журнал действий честно отражает решения keep/defer.

## Управление Downloads и остановка сидирования

Read model Downloads нормализует наблюдения всех включённых клиентов. Поле,
которое клиент не передал, остаётся nullable/unknown; оно никогда не заменяется
нулём или успешным чтением. Списки ограничены и используют cursor, а partial
результат source остаётся явно partial.

Downloads предоставляет только обратимые controls **pause** и **resume**, а не
удаление entry или data. Ручное действие требует fresh managed observation и
client-generated idempotency key. Состояниями завершения являются только
`succeeded`, `already_in_state` и dry-run `simulated`. Для `failed`,
`uncertain` и `reconcile_required` нужен review оператора; ambiguous request
повторяйте с точно тем же action и idempotency key.

Глобальная automatic seeding-stop policy отделена от per-profile removal policy
выше и по умолчанию отключена. Она только ставит раздачу на паузу, когда fresh
managed seeding evidence достигает настроенного порога ratio и/или времени.
Режим выбирается явно (`all` или `any`), category/tag include/exclude scope
работает fail closed, а отсутствие обязательной метрики блокирует действие.
Policy никогда не удаляет torrent entry или локальные data.

## Безопасность удаления данных в rTorrent

Команда rTorrent `d.erase` удаляет раздачу, но специально не трогает данные. В
режиме удаления с данными CleanArr получает путь раздачи через XML-RPC,
отклоняет пустые, относительные, содержащие переход к родителю и корневые пути,
останавливает и закрывает раздачу, вызывает `execute.throw` с отдельными
аргументами `/bin/rm -rf --`, а затем выполняет `d.erase`.

Поэтому XML-RPC endpoint rTorrent должен разрешать `execute.throw`, а процесс
rTorrent — иметь права на удаление своих данных. Используйте отдельный
аутентифицированный RPC endpoint и системного пользователя с ограниченным
доступом к файловой системе. Если проверка пути или команда завершается
ошибкой, CleanArr не удаляет раздачу из rTorrent и фиксирует failed action.

## Статус совместимости

Для адаптеров есть автоматизированные protocol contract tests: определение
поколения Transmission, v1/v2 hybrid identifiers qBittorrent, ошибки
аутентификации, отсутствующие hashes, оба режима удаления, seeding thresholds,
частичная ошибка при нескольких клиентах и отклонение небезопасного пути
rTorrent. Release gate также запускает адаптеры на digest-pinned реальных
сервисах. Точные сертифицированные версии, граница доказательств и support policy
1.x опубликованы в [матрице совместимости](COMPATIBILITY_RU.md).
