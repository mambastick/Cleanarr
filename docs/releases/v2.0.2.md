## Русский

### Изменения

- Усилена fail-closed защита удаления: если история Radarr или Sonarr не
  предоставляет download hash, CleanArr теперь блокирует destructive plan,
  вместо продолжения очистки без доказанного ownership. Узкое исключение
  сохраняется только для плана, который явно доказывает отсутствие физических
  файлов.
- Confirmation hash больше не зависит от быстро меняющихся ratio, seeding time
  и presentation-текста. Identity, policy, действия, статусы и причины остаются
  привязаны к подтверждению, поэтому безопасный план не получает ложный
  `plan_changed` только из-за обновившейся telemetry.
- Завершённая dry-run операция теперь явно показывается как симуляция без
  изменений, а после terminal deletion job библиотека принудительно обновляется
  из источника, чтобы удалённая карточка не оставалась в интерфейсе.
- До загрузки authoritative runtime state интерфейс показывает нейтральный
  unknown mode и блокирует single/batch deletion planning, downloader controls
  и manual download refresh с видимой причиной.
- Package-smoke CI получил конечные deadlines, ограниченные network
  retries/timeouts и гарантированную очистку test containers после timeout или
  interruption.

### Обновление

Обновление с v2.0.1 не меняет schema SQLite или runtime configuration. Перед
заменой image всё равно создайте и выгрузите проверенный SQLite backup по
[Docker-инструкции](https://github.com/mambastick/Cleanarr/blob/v2.0.2/README_RU.md#быстрый-запуск)
или
[инструкции для нативного пакета](https://github.com/mambastick/Cleanarr/blob/v2.0.2/docs/LINUX_PACKAGES_RU.md#резервное-копирование).
Сохраните предыдущий image `2.0.1` и `cleanarr.config-v3.backup.db` для
rollback. Не запускайте destructive actions во время обновления; после запуска
повторно проверьте representative previews, runtime mode и ownership evidence
перед первым удалением.

## English

### Changes

- Strengthened fail-closed deletion safety: when Radarr or Sonarr history does
  not provide a download hash, CleanArr now blocks the destructive plan instead
  of continuing cleanup without proven ownership. The narrow exception remains
  only for a plan that explicitly proves there are no physical files.
- Confirmation hashes no longer depend on rapidly changing ratio, seeding time,
  or presentation text. Identity, policy, actions, statuses, and reasons remain
  confirmation-bound, so a safe plan does not receive a false `plan_changed`
  merely because telemetry advanced.
- A completed dry-run operation is now identified as a no-change simulation,
  and Library is force-refreshed from source after a terminal deletion job so a
  deleted card does not remain visible.
- Until authoritative runtime state loads, the UI shows a neutral unknown mode
  and disables single/batch deletion planning, downloader controls, and manual
  download refresh with a visible reason.
- Package-smoke CI now has finite deadlines, bounded network retries/timeouts,
  and guaranteed test-container cleanup after a timeout or interruption.

### Upgrade

Upgrading from v2.0.1 does not change the SQLite or runtime-configuration
schema. Before replacing the image, still create and export a verified SQLite
backup using the
[Docker procedure](https://github.com/mambastick/Cleanarr/blob/v2.0.2/README.md#quick-start)
or
[native-package procedure](https://github.com/mambastick/Cleanarr/blob/v2.0.2/docs/LINUX_PACKAGES.md#backup).
Retain the previous `2.0.1` image and `cleanarr.config-v3.backup.db` for
rollback. Do not run destructive actions during the upgrade; after startup,
revalidate representative previews, runtime mode, and ownership evidence before
the first deletion.
