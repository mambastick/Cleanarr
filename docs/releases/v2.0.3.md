## Русский

### Изменения

- Страница Library теперь адаптирует варианты количества постеров к фактическому
  числу колонок при текущей ширине окна и размере карточек. Каждый вариант
  заполняет последний ряд целиком, поэтому после выбора большего количества на
  странице больше не остаются пустые места из-за несовпадения фиксированных
  значений `12 / 24 / 48` с responsive-сеткой.
- Пересчёт выполняется при изменении ширины окна и размера карточек, сохраняя
  привычные уровни объёма страницы и стабильную пагинацию. Для загрузочного
  состояния Library также уточнены accessible section/status semantics без
  дублирования skeleton-контента для screen reader.

### Обновление

Обновление с v2.0.2 не меняет schema SQLite или runtime configuration. Перед
заменой image всё равно создайте и выгрузите проверенный SQLite backup по
[Docker-инструкции](https://github.com/mambastick/Cleanarr/blob/v2.0.3/README_RU.md#быстрый-запуск)
или
[инструкции для нативного пакета](https://github.com/mambastick/Cleanarr/blob/v2.0.3/docs/LINUX_PACKAGES_RU.md#резервное-копирование).
Сохраните предыдущий image `2.0.2` и проверенный backup для rollback. Не
запускайте destructive actions во время обновления; после запуска повторно
проверьте representative previews, runtime mode и ownership evidence перед
первым удалением.

## English

### Changes

- The Library page now adapts its poster-count options to the actual number of
  columns at the current viewport width and card size. Every option fills the
  final row, so choosing a larger page no longer leaves empty grid positions
  when the fixed `12 / 24 / 48` values do not divide the responsive column
  count.
- The values are recalculated when the viewport or card size changes while
  preserving the familiar page-volume tiers and stable pagination. The Library
  loading state also has clearer accessible section/status semantics without
  exposing duplicate skeleton content to screen readers.

### Upgrade

Upgrading from v2.0.2 does not change the SQLite or runtime-configuration
schema. Before replacing the image, still create and export a verified SQLite
backup using the
[Docker procedure](https://github.com/mambastick/Cleanarr/blob/v2.0.3/README.md#quick-start)
or
[native-package procedure](https://github.com/mambastick/Cleanarr/blob/v2.0.3/docs/LINUX_PACKAGES.md#backup).
Retain the previous `2.0.2` image and verified backup for rollback. Do not run
destructive actions during the upgrade; after startup, revalidate
representative previews, runtime mode, and ownership evidence before the first
deletion.
