## Русский

### Изменения

- Ручное удаление получило явную state machine, устойчивое display name и
  персистентную идемпотентность: одно подтверждение создаёт ровно одно задание,
  а неоднозначный или изменившийся план по-прежнему блокируется fail closed.
- Добавлено ограниченное массовое удаление до 50 элементов с mutation-free
  child plans, одним hash-bound подтверждением и честными per-item partial
  outcomes без имитации общей транзакции между внешними сервисами.
- Новый раздел «Загрузки» нормализует состояние qBittorrent, Transmission,
  Deluge и rTorrent и предоставляет только обратимые pause/resume actions с
  fresh ownership evidence, идемпотентностью и аудитом. Stop policy отключена
  по умолчанию и никогда не удаляет раздачу или данные.
- Кандидаты очистки используют ограниченные Jellyfin playback-сигналы для
  сортировки и объяснений. Missing, stale или conflicting данные остаются
  unknown, а watch history никогда не становится доказательством владения или
  разрешением на удаление.
- Мастер первого запуска поддерживает несколько torrent-профилей с отдельными
  полями и connection-test fingerprint для qBittorrent, Transmission, Deluge и
  rTorrent. Изменение проверенного draft немедленно сбрасывает readiness.
- Frontend переведён на локальные shadcn/Base UI primitives, semantic OKLCH
  tokens и доступные Dialog, Sheet, Select, Checkbox и animated Tabs. Добавлены
  English/Russian copy, reduced-motion, keyboard/focus, mobile overflow,
  Vitest/Testing Library и Playwright/Axe gates.
- SQLite schema v5 и config schema v3 добавляют batch, download observation,
  reversible action и policy records через последовательные additive migrations.
  Upgrade с v1.0.0 и rollback через проверенный backup входят в обязательный
  release gate.

### Обновление

Перед обновлением создайте и выгрузите проверенный SQLite backup по инструкции
для [Docker](../../README_RU.md#быстрый-запуск) или
[нативного пакета](../LINUX_PACKAGES_RU.md#резервное-копирование). Сохраните
предыдущий image/package и соответствующий backup. После обновления оставьте
`DRY_RUN=true`, перепроверьте все включённые профили и representative single/
batch previews, и только затем включайте нужные мутации или stop policy.

## English

### Changes

- Manual deletion now has an explicit state machine, stable display names, and
  durable idempotency: one confirmation creates exactly one job, while an
  ambiguous or changed plan still fails closed.
- Added bounded batch deletion for up to 50 items with mutation-free child
  plans, one hash-bound confirmation, and explicit per-item partial outcomes
  instead of pretending that external services share one transaction.
- The new Downloads section normalizes qBittorrent, Transmission, Deluge, and
  rTorrent state and exposes reversible pause/resume actions only, guarded by
  fresh ownership evidence, idempotency, and audit records. The stop policy is
  disabled by default and never removes torrent entries or data.
- Cleanup candidates use bounded Jellyfin playback signals for sorting and
  explanations. Missing, stale, or conflicting data remains unknown, and watch
  history never becomes ownership evidence or deletion authority.
- First-run setup supports multiple downloader profiles with client-specific
  fields and a connection-test fingerprint for qBittorrent, Transmission,
  Deluge, and rTorrent. Editing a tested draft immediately invalidates readiness.
- The frontend now uses local shadcn/Base UI primitives, semantic OKLCH tokens,
  and accessible Dialog, Sheet, Select, Checkbox, and animated Tabs components.
  English/Russian copy, reduced motion, keyboard/focus, mobile overflow,
  Vitest/Testing Library, and Playwright/Axe gates are included.
- SQLite schema v5 and config schema v3 add batch, download-observation,
  reversible-action, and policy records through ordered additive migrations.
  Upgrade from v1.0.0 and rollback through a verified backup are mandatory
  release gates.

### Upgrade

Before upgrading, create and export a verified SQLite backup using the
[Docker](../../README.md#quick-start) or
[native-package](../LINUX_PACKAGES.md#backup) procedure. Keep the previous
image/package and its matching backup. After upgrading, retain `DRY_RUN=true`,
retest every enabled profile and representative single/batch previews, and only
then enable the intended mutations or stop policy.
