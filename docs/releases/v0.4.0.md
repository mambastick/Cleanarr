## Русский

### Изменения

- Завершена безопасная обработка удаления эпизодов в Seerr: связанные проблемы очищаются, а сезонный запрос изменяется только при доказанном охвате всего сезона.
- Seerr стал каноническим именем в API, UI, логах и конфигурации; существующие профили Jellyseerr мигрируют без потери данных, а legacy-псевдонимы остаются совместимыми.
- Ручное удаление теперь требует точного dry-run плана и подтверждения его SHA-256 hash; изменившийся, неоднозначный или ошибочный план отклоняется до первой мутации.
- Ручные задания, исходное событие, подтверждённый план, частичный результат и retry schedule сохраняются в SQLite и безопасно продолжаются после рестарта.
- Добавлены версии схемы SQLite 1 и 2, последовательные миграции, проверяемый backup/restore и документированные процедуры rollback для контейнера и нативных пакетов.
- Успешные повторные webhook events подавляются семь дней, включая рестарты; partial failure и ignored events остаются доступными для безопасного retry.
- Webhook, фоновые ручные задания и legacy endpoint используют единую process-wide блокировку, исключающую пересечение разрушительных операций в одном экземпляре CleanArr.
- Ошибка удаления torrent блокирует зависимые изменения Arr, Seerr и Jellyfin, сохраняя ownership evidence для следующей попытки.
- Backend suite расширен до 96 тестов; обязательные quality gates также проверяют Ruff, strict mypy, frontend, контейнер и установленные DEB/RPM.

### Ограничения этапа

- Горизонтальное масштабирование, PostgreSQL и HA не входят в границы CleanArr 1.0; сериализация v0.4 рассчитана на один экземпляр приложения.
- Security baseline, support tooling и метрики запланированы на v0.5.0.
- Сертификация на матрице реальных версий сервисов остаётся gate этапа v0.9.0.

## English

### Changes

- Completed safe episode deletion handling in Seerr: matching issues are removed, while a season-scoped request changes only when full-season coverage is proven.
- Made Seerr the canonical name in the API, UI, logs, and configuration; existing Jellyseerr profiles migrate without data loss and legacy aliases remain compatible.
- Manual deletion now requires an exact dry-run plan and confirmation of its SHA-256 hash; changed, ambiguous, or failed plans are rejected before the first mutation.
- Manual jobs, source events, confirmed plans, partial results, and retry schedules are persisted in SQLite and resume safely after a restart.
- Added SQLite schema versions 1 and 2, ordered migrations, verified backup/restore, and documented rollback procedures for containers and native packages.
- Successful duplicate webhook events are suppressed for seven days across restarts; partial failures and ignored events remain eligible for a safe retry.
- Webhooks, queued manual jobs, and the legacy endpoint share one process-wide lock that prevents overlapping destructive operations within a CleanArr instance.
- A torrent-removal failure blocks dependent Arr, Seerr, and Jellyfin mutations, preserving ownership evidence for the next attempt.
- Expanded the backend suite to 96 tests; required quality gates also verify Ruff, strict mypy, the frontend, the container, and installed DEB/RPM packages.

### Milestone limits

- Horizontal scaling, PostgreSQL, and HA are outside the CleanArr 1.0 product boundary; v0.4 serialization targets a single application instance.
- The security baseline, support tooling, and metrics remain scheduled for v0.5.0.
- Certification against a matrix of real service versions remains a v0.9.0 gate.
