## Русский

### Изменения

- CleanArr получил новый production UI: адаптивные sidebar/rail/mobile
  navigation, компактный мастер настройки, переработанные Dashboard, Library,
  Downloads, Cleanup Candidates, Activity, Users и Settings, согласованные
  light/dark темы, keyboard/focus states и reduced-motion режим.
- Новый resource-based Library API объединяет фильмы и сериалы из настроенных
  Arr/Jellyfin сервисов, отдаёт ограниченные cursor-страницы и приватный artwork.
  Dashboard показывает нормализованное состояние storage без раскрытия raw
  paths; missing, stale, partial и conflicting evidence остаётся `unknown`.
- Добавлены сохраняемые роли `admin` и `viewer`. Viewer получает только
  ограниченные read projections; конфигурация, credentials, каталог
  пользователей, refresh/controls и любые mutation остаются доступны только
  администраторам. Последнего администратора нельзя понизить.
- SQLite schema v6 добавляет проекцию учётных записей, а runtime configuration
  schema v4 — пороги свободного места. Обе миграции выполняются последовательно;
  перед записью config v4 автоматически создаётся проверяемый rollback-sidecar
  schema v3.
- Версия 2.0 обозначает замену production UI и новую authenticated-границу
  administrator/viewer. Она сохраняет fail-closed deletion contract,
  dry-run-by-default и поддержку qBittorrent, Transmission, Deluge и rTorrent,
  сертифицированную в серии 1.x.

### Обновление

Перед обновлением с v1.1.0 создайте и выгрузите проверенный SQLite backup по
инструкции для
[Docker](https://github.com/mambastick/Cleanarr/blob/v2.0.0/README_RU.md#быстрый-запуск)
или
[нативного пакета](https://github.com/mambastick/Cleanarr/blob/v2.0.0/docs/LINUX_PACKAGES_RU.md#резервное-копирование).
Сохраните
предыдущий image/package и автоматически созданный
`cleanarr.config-v3.backup.db`. После обновления проверьте вход администратора,
роли пользователей, storage thresholds и все включённые integrations. Оставьте
`DRY_RUN=true`, пока representative previews и ownership evidence не будут
проверены заново.

## English

### Changes

- CleanArr now ships a new production UI with responsive sidebar/rail/mobile
  navigation, a compact setup wizard, redesigned Dashboard, Library, Downloads,
  Cleanup Candidates, Activity, Users, and Settings, coordinated light/dark
  themes, keyboard/focus states, and reduced-motion behavior.
- A new resource-based Library API joins movies and series from configured
  Arr/Jellyfin services into bounded cursor pages and private artwork. The
  Dashboard reports normalized storage state without exposing raw paths;
  missing, stale, partial, or conflicting evidence remains `unknown`.
- Persisted `admin` and `viewer` roles are now available. Viewers receive only
  bounded read projections; configuration, credentials, the user directory,
  refresh/controls, and every mutation remain administrator-only. The final
  administrator cannot be demoted.
- SQLite schema v6 adds the account projection, while runtime configuration
  schema v4 adds free-space thresholds. Both migrate in order, and a verified
  schema-v3 rollback sidecar is created automatically before config v4 is
  persisted.
- Version 2.0 identifies the production UI replacement and the new authenticated
  administrator/viewer boundary. It carries forward the fail-closed deletion
  contract, dry-run-by-default behavior, and qBittorrent, Transmission, Deluge,
  and rTorrent support certified in the 1.x series.

### Upgrade

Before upgrading from v1.1.0, create and export a verified SQLite backup using
the
[Docker](https://github.com/mambastick/Cleanarr/blob/v2.0.0/README.md#quick-start)
or
[native-package](https://github.com/mambastick/Cleanarr/blob/v2.0.0/docs/LINUX_PACKAGES.md#backup)
procedure. Retain the previous
image/package and the automatically created `cleanarr.config-v3.backup.db`.
After upgrading, verify administrator login, user roles, storage thresholds,
and every enabled integration. Keep `DRY_RUN=true` until representative
previews and ownership evidence have been revalidated.
